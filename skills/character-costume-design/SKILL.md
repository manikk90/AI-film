# Character and costume design

Inputs: screenplay/beat breakdown, treatment, character appearances by scene, supplied identity references. Follow [asset rules](../../docs/SOP.md) and [asset contract](../../docs/CONTRACT.md).

Separate immutable identity from scene-specific looks. Define face, age appearance, proportions and distinguishing features; then hair, makeup, costume, accessories, footwear, injury, dirt and wetness. Keep script-defined details exact and label inferred choices.

Use a canonical identity image to derive needed front/three-quarter/profile and full-body views. Generate only views and costume variants the planned coverage needs. For each costume specify silhouette, fabric, fit, colour, layers and worn state. Record which scenes use which look and what events cause changes.

Inspect actual images for identity/wardrobe agreement. A turnaround that contains different faces is not accepted just because the prompt requested consistency. Repair the affected design before passing it downstream. If no image tool is accessible, deliver the design briefs and ungenerated status; do not register imaginary paths.

Register real images with versioned `add-asset` IDs. Record derivation when a costume view or later look uses canonical references. Keep an asset-design note with chosen identity/look IDs and observed review findings. Registration itself does not mark a design visually approved.

Output: design briefs, real canonical/reference images when generated, scene-to-look mapping and explicit outstanding design issues. Escalate major reinterpretations, not routine garment details.
