## Select the deliverable

| Request | Deliver | Keep internal |
|---|---|---|
| "Explain art direction" | Useful explanation and examples | Production pipeline |
| "Research properly" | Sourced study with limits and proposed applications | Unnecessary asset generation |
| "Design this scene" | Concrete visual direction and relevant choices | Full unrelated project audit |
| "Only prompt" | Copy-ready prompt(s) | Reasoning, global locks and references list |
| "Detailed panel" | Relevant deep beat/coverage plan or requested cell prompts | Unrelated later scenes |
| "Correct this frame" | Actual edit when requested and tools available | A substitute storyboard |
| "Build a campaign" | Concept plus coherent adaptation system | Automatic film-only constraints |

Reuse approved context. Missing essential identity/reference assets block only dependent execution; continue unaffected research/planning. Do not fabricate a source to finish a template.

## Art-direction brief

Use proportionally; omit empty sections from user-facing micro-edits.

```
Source / version / requested deliverable:
Audience and viewing conditions:
Intended inference / emotion:
Visible evidence supporting it:
World facts: place, period, inhabitants, use:
Approved locks and exact reference roles:
Open design choices:
Selected mechanism and why:
Palette/material roles; motivated source logic:
Spatial/action requirements:
Execution approach and actual capabilities:
Acceptance evidence; known unknowns:
```

Keep factual source evidence separate from proposals. An inferred default must not silently become owner-approved canon. A documented instruction is not a generated/accepted asset.

## Reference analysis

For each useful reference record:
1. Original URL/file, creator/institution and inspection extent.
2. Exact feature observed or stated by the source.
3. First read and essential relation: hierarchy, grouping, material, space, metaphor or sequence.
4. Mechanism transferable to this brief.
5. Inventory/style fields that must not be imported.
6. Proposed application and falsifiable failure: what would show it did not work?

**Example:** A source image uses a doorway to group two participants. Transfer the boundary/grouping relation only where an actual approved opening exists. Do not copy its doorway architecture, costumes, people or palette.

Do not call a source's interpretation a universal perceptual fact. Attribute critic readings. Verify current product features from current official documentation before making tool-specific promises. The bundled sources are dated research, not live product verification.

## World and asset records

Use the active project's authoritative schema. Do not create a parallel canon merely to fill these fields.

| Record | Minimum useful fields |
|---|---|
| World/master | Version, geometry, entries, connected views, source logic, approval |
| Character/look | Exact identity binding, approved costume/hair, scoped state and reference roles |
| Prop | Owner, dimensions/material, support/contact, orientation, current state |
| Shot-local inventory | Visible/required entities, crop extent, exact view binding, source version |
| Decision | Fact/proposal/approval, scope, reason, affected dependencies |

Preserve existing gates. For a new location using master-first, resolve one master before dependent angles when required by that workflow. Do not impose master approval again on a fully specified single-shot rewrite.

## Shot compilation

Internally perform:

```
scene_state = latest approved source + scoped overrides
camera = requested/selected feasible view around stable blocking
visible = entities and local background inside camera's crop
required = contact owners/reference bindings/audio actually needed for this shot
prompt = visible + relevant required directions
remove = story synopsis, future beats, unrelated entities, global inventories
check = exact tags + local angle + locks + action/instant + requested format
```

This is reasoning pseudocode, not an implemented visibility engine. Do not claim geometric proof from this list.

Default still form: `[shot ID if supplied] [size/angle]: subject + selected instant + local view + concrete focus/composition + relevant light.`

Default video form: `[duration if supplied] [shot ID] [size/angle]: subject + feasible action + camera/focus + relevant local setting/locked light. DIALOGUE as final paragraph only when needed.`

Keep duration and supplied shot IDs unchanged unless requested. Include exact approved location-angle tags for the visible setting where the tool/workflow requires them, including close-ups with a local background. Do not replace an unavailable tag with a plausible invented one. State the missing binding outside executable content.

For inserts, identify whose visible hands/fragment and which object/contact appear; omit invisible face, full outfit and offscreen participants. For offscreen dialogue, distinguish the audio owner from visual inventory. Never add the character to the frame to justify the line.

## Detailed panels

Map a beat through preparation, decisive event, response and consequence, only where present/needed. Select an instant for each cell. Cover emotional processing, object contact and meaningful environment traces. Do not duplicate the same beat with cosmetic angle changes merely to fill a grid.

Use a compact internal table: `beat -> new information/emotion -> selected instant -> coverage purpose -> local bindings -> transition`. If the user requests only prompts, deliver only the compiled cell entries. Avoid global SCENE/LOCATION LOCK preambles that repeat the whole cast, setup and constraints.

Explore relationships within fixed blocking: clean two-shot, relevant edge OTS, profile, deeper relation, isolating reaction, informative insert. Do not repeat blurred foregrounds automatically. A strict supplied frame takes priority over experiments.

## Posters/campaigns

Start with message, audience, medium and exact approved copy. Explore mechanisms before execution styles. Select a master concept, then state invariant and variable rules:
- Invariant: core relation, recognisable device, palette/type roles, exact approved marks.
- Variable: subject/crop/format/adaptation when allowed.
- Readability: first read, hierarchy, intended reading distance/time and platform requirements if verified.
- Motion: meaningful development of the same concept, not arbitrary animation.

Avoid claiming a campaign works commercially from its appearance or a designer's account alone. Do not import poster text/graphic borders into a literal film scene unless asked.

## Learning and handoff

Treat user corrections as scoped requirements. Record durable reusable rules only through authorised persistence. Keep research hypotheses separate from tested practices. Test a candidate on a relevant case and known failure before describing it as a proven improvement. Do not claim all-chat access, passive self-training or schedules from a saved skill.

Hand back the actual requested artifact, source/asset version, decisions affecting the next role, what was inspected and material pending issues. Mention an unknown only when it affects use; avoid a generic disclaimer list.
